Tiled matrix multiplication

Ketan Suhaas Saichandran
gpumatmultilingshared-memoryarithmetic-intensity

Builds on: The CUDA programming model, Arithmetic intensity and the roofline · Leads to: Floating point and mixed precision

Each value of $A$ and $B$ is needed by $n$ different outputs. Fetch it from HBM once per tile, park it in shared memory, and use it $T$ times.

Naive: one thread per output

Thread $(i,j)$ walks row $i$ of $A$ and column $j$ of $B$ on its own. Its neighbours fetch the same rows and columns again.

$$C_{ij}=\sum_{k=1}^{n}A_{ik}B_{kj}:\qquad \underbrace{n}_{\text{row of }A}+\underbrace{n}_{\text{column of }B}=2n \text{ reads per output}.$$

$$\text{reads}=\underbrace{n^2}_{\text{outputs}}\cdot2n=2n^3,\qquad \text{FLOPs}=n^2\cdot\underbrace{2n}_{n\text{ mul}+n\text{ add}}=2n^3.$$

One value read per FLOP, so with $s$-byte values

$$I=\frac{2n^3}{2n^3\cdot s}=\frac1s\ \text{FLOP/B}=0.5\ \text{in fp16}.$$

Far down the roofline's slope.

Tiled: load once, reuse $T$ times

A block owns a $T\times T$ tile of $C$. It marches along $k$; each step copies one tile of $A$ and one of $B$ into shared memory, and every thread does $T$ multiply-adds from that fast copy.

__shared__ float As[T][T], Bs[T][T];          // T = 32: 1024 threads
int r = threadIdx.y, c = threadIdx.x;         // one thread per C element
int i = blockIdx.y * T + r, j = blockIdx.x * T + c;
float acc = 0.0f;
for (int k0 = 0; k0 < n; k0 += T) {
    As[r][c] = A[i * n + k0 + c];             // each thread loads one value
    Bs[r][c] = B[(k0 + r) * n + j];
    __syncthreads();                          // tiles are complete
    for (int k = 0; k < T; ++k) acc += As[r][k] * Bs[k][c];
    __syncthreads();                          // done before overwriting
}
C[i * n + j] = acc;

Count the loads. $C$ is cut into $(n/T)^2$ tiles, one block each. A block walks $k$ in steps of $T$, so it takes $n/T$ steps. Each step, each of the $T^2$ threads loads one value of $A$ and one of $B$ (the two load lines in the loop):

$$\underbrace{(n/T)^2}_{\text{blocks}}\cdot\underbrace{n/T}_{\text{steps}}\cdot\underbrace{2T^2}_{\text{values per step}}=\frac{2n^3}{T}\ \text{reads}.$$

Intensity. The FLOPs are unchanged ($2n^3$), only the reads shrink:

$$I=\frac{2n^3}{(2n^3/T)\cdot s}=\frac Ts\ \text{FLOP/B}=\frac T2\ \text{in fp16}.$$

Same answer per step, as a check: the block does $T^2$ outputs $\times\,T$ multiply-adds $=2T^3$ FLOPs on $2T^2$ loaded values, so $I=2T^3/(2T^2s)=T/s$. Each loaded value As[r][k] is used by all $T$ threads of row $r$: that factor $T$ is the reuse.

Example: $T=128$ (real kernels, each thread computing several outputs)

$$I=\frac{128}{2}=64\ \text{FLOP/B},\qquad \frac{64}{0.5}=128\times\ \text{the naive kernel}.$$

Why not just pick $T$ large enough for the A100 ridge (~156) from HBM alone? That needs $T/2\ge156$, i.e. $T\ge312$. The block's $T^2$ fp32 accumulators must live in registers (256 KB per SM, see memory hierarchy):

$$T=128:\ 128^2\cdot4\ \text{B}=64\ \text{KB}\ \checkmark,\qquad T=312:\ 312^2\cdot4\ \text{B}\approx380\ \text{KB}\gt256\ \text{KB}.$$

So tile size stops short of the ridge. The rest comes from neighbouring blocks sharing tiles through L2, which carries big matmuls past the ridge.

Tensor cores

Tensor cores multiply small matrix tiles in one instruction (bf16/fp16 in, fp32 accumulate): ~312 TFLOP/s on an A100 vs ~19.5 on its plain FP32 lanes. Tiling is what keeps them fed.

Both peaks are computed in Why GPUs (units $\times$ clock $\times$ FLOPs per cycle). Their ratio is what raises the bar:

$$\frac{312}{19.5}=16\times\text{ more math}\ \Rightarrow\ \text{ridge }\frac{312}{2}=156\text{ instead of }\frac{19.5}{2}\approx10\ \text{FLOP/B}.$$

Without tiling ($I=0.5$) even the plain lanes would starve.

Work it out yourself

$n=4096$, fp16. HBM bytes read by the naive kernel vs tiled with $T=128$? At ~2 TB/s, how long does each take, next to the math at ~312 TFLOP/s?

Solution

$n^3=4096^3=2^{36}\approx6.87\times10^{10}$. Bytes are values $\times\,2$ B, time is bytes $/\ 2\times10^{12}$ B/s.

$$\text{naive: }2n^3\approx1.37\times10^{11}\ \text{values}\ \to\ 275\ \text{GB},$$

$$\frac{2.75\times10^{11}\ \text{B}}{2\times10^{12}\ \text{B/s}}\approx137\ \text{ms}.$$

$$\text{tiled: }\frac{2n^3}{128}\approx1.07\times10^{9}\ \text{values}\ \to\ 2.15\ \text{GB}\ \to\ \approx1.1\ \text{ms}.$$

$$\text{math: }\frac{2n^3}{3.12\times10^{14}}=\frac{1.37\times10^{11}}{3.12\times10^{14}}\approx0.44\ \text{ms}.$$

By the roofline, $t=\max(\text{math},\text{memory})$: naive $\approx137$ ms, tiled $\approx1.1$ ms. L2 reuse and larger tiles close the rest, so a tuned kernel runs near the 0.44 ms compute bound. The floor is reading $A$ and $B$ once:

$$2n^2\cdot2\ \text{B}=4\cdot4096^2\ \text{B}\approx67\ \text{MB}\ \to\ 0.034\ \text{ms}.$$
