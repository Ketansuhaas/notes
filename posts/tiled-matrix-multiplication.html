Tiled matrix multiplication

Ketan Suhaas Saichandran
gpumatmultilingshared-memoryarithmetic-intensity

Builds on: The CUDA programming model, Arithmetic intensity and the roofline · Leads to: Floating point and mixed precision

Each value of $A$ and $B$ is needed by $n$ different outputs. Fetch it from HBM once per tile, park it in shared memory, and use it $T$ times.

Naive: one thread per output

Thread $(i,j)$ walks row $i$ of $A$ and column $j$ of $B$ on its own. Its neighbours fetch the same rows and columns again.

$$C_{ij}=\sum_{k=1}^{n}A_{ik}B_{kj}:\qquad 2n \text{ reads per output},\quad n^2\cdot2n=2n^3 \text{ reads in total}.$$

One value read per FLOP: $I=1/s$ FLOP/B for $s$-byte values, $0.5$ in fp16. Far down the roofline's slope.

Tiled: load once, reuse $T$ times

A block owns a $T\times T$ tile of $C$. It marches along $k$; each step copies one tile of $A$ and one of $B$ into shared memory, and every thread does $T$ multiply-adds from that fast copy.

__shared__ float As[T][T], Bs[T][T];          // T = 32: 1024 threads
int r = threadIdx.y, c = threadIdx.x;         // one thread per C element
int i = blockIdx.y * T + r, j = blockIdx.x * T + c;
float acc = 0.0f;
for (int k0 = 0; k0 < n; k0 += T) {
    As[r][c] = A[i * n + k0 + c];             // each thread loads one value
    Bs[r][c] = B[(k0 + r) * n + j];
    __syncthreads();                          // tiles are complete
    for (int k = 0; k < T; ++k) acc += As[r][k] * Bs[k][c];
    __syncthreads();                          // done before overwriting
}
C[i * n + j] = acc;

$$\underbrace{(n/T)^2}_{\text{blocks}}\cdot\underbrace{n/T}_{\text{steps}}\cdot\underbrace{2T^2}_{\text{values per step}}=\frac{2n^3}{T}\ \text{reads}.$$

naive$2n^3$$0.5$ FLOP/B
tiled$2n^3/T$$T/2$ FLOP/B

Example: $T=128$ (real kernels, each thread computing several outputs)

$I=64$ FLOP/B, a $128\times$ climb up the roofline. Neighbouring blocks also share tiles through L2, which carries big matmuls past the A100 ridge (~156).

Tensor cores

Tensor cores multiply small matrix tiles in one instruction (bf16/fp16 in, fp32 accumulate): ~312 TFLOP/s on an A100 vs ~19.5 on its plain FP32 lanes. Tiling is what keeps them fed.

Work it out yourself

$n=4096$, fp16. HBM bytes read by the naive kernel vs tiled with $T=128$? At ~2 TB/s, how long does each take, next to the math at ~312 TFLOP/s?

Solution

Naive: $2n^3\approx1.37\times10^{11}$ values $\approx275$ GB, about $140$ ms.

Tiled: $\div128$: $1.07\times10^{9}$ values $\approx2.1$ GB, about $1.1$ ms.

Math: $1.37\times10^{11}$ FLOPs $/\,3.12\times10^{14}\approx0.44$ ms. Tiling turns a 140 ms stall into ~1 ms; L2 reuse and larger tiles close the rest, so a tuned kernel runs near the 0.44 ms compute bound. (The floor: read $A$ and $B$ once, $2n^2\cdot2$ B $\approx67$ MB.)
