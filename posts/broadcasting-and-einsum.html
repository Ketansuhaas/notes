Broadcasting and einsum

Ketan Suhaas Saichandran

Builds on: Tensors: shape, dtype, device, and strides, Four views of matrix multiplication · Leads to: Autograd in PyTorch

Two ways to say "do this for every index" without a loop. Broadcasting repeats a tensor along missing axes; einsum names the axes and says which ones to sum.

Broadcasting: align right, stretch the 1s

Line the shapes up from the right. Each pair of sizes must match, or one of them is $1$ (or missing) and gets stretched.

ShapesResultUse
(3, 1) + (1, 4)(3, 4)all pairs $a_i+b_j$
(B, T, 64) + (64,)(B, T, 64)add a bias everywhere
(B, 1, D) − (1, N, D)(B, N, D)pairwise differences
(3,) + (4,)error$3\ne4$, neither is $1$

Step 1: a size-1 axis can take stride 0

Stretching is not copying. A stride-0 axis reads the same element for every index along it, so the "copies" cost nothing.

a = arange(3).view(3, 1) has strides $(1,1)$ by the address rule ($s_0=n_1s_1=1$). Its only legal index on axis 1 is $0$, so $s_1$ is never used. Set $s_1=0$ and allow $j=0,\dots,3$:

$$\text{offset}(i,j)=i\cdot1+j\cdot0=i\quad\Rightarrow\quad a_{\text{exp}}[i,j]=a[i]\ \text{ for every } j.$$

Likewise b = arange(4).view(1, 4) has strides $(4,1)$; zero the size-1 axis to get $(0,1)$, offset $=j$, so $b_{\text{exp}}[i,j]=b[j]$. Then

$$c[i,j]=a[i]+b[j]=i+j,$$

e.g. row 2 is $2,3,4,5$, as in the figure. Memory: inputs $3+4$ floats, only the $3\cdot4=12$ outputs are new.

Step 2: the rules are the conditions for Step 1

Each broadcasting rule is exactly what is needed for a stride-0 view to pair every output index with one input element.

Missing axes go on the left. A new size-1 axis always has index $0$, so it adds $0\cdot s$ to every offset: shape $(n,)$ and $(1,n)$ read the same elements. PyTorch adds the missing axes on the left, which is why shapes are aligned from the right.

Per axis, with sizes $n_a,n_b$ after padding:

$$n_a=n_b:\ \text{pair index } i \text{ with } i;\qquad n_a=1:\ s_a\leftarrow0,\ \text{size}\leftarrow n_b.$$

If $n_a\ne n_b$ and neither is $1$, index $n_a$ of the longer one has no partner: error. The output size per axis is $\max(n_a,n_b)$. Applying this to the table:

$$(64,)\to(1,1,64),\ \text{strides }(0,0,1):\quad \text{out}[b,t,d]=x[b,t,d]+\text{bias}[d].$$

$$(B,1,D)\text{ and }(1,N,D):\quad \text{out}[b,n,d]=x[b,0,d]-y[0,n,d].$$

The last one allocates $B\cdot N\cdot D$ new elements even though the inputs hold only $(B+N)D$: the stretch is free, the output is not.

a = torch.arange(3.).view(3, 1)    # column
b = torch.arange(4.).view(1, 4)    # row
(a + b).shape                      # (3, 4)
a.expand(3, 4).stride()            # (1, 0): stride 0, no copy
x = torch.randn(32, 128)
(x - x.mean(0)).shape              # (32, 128): center every column

x.mean(0) has shape $(128,)$, padded to $(1,128)$, stretched with stride $0$ down the rows:

$$\text{out}[i,j]=x[i,j]-\mu_j,\qquad \mu_j=\tfrac1{32}\textstyle\sum_{i}x[i,j].$$

Step 3: einsum is a loop nest

Give every axis a letter. The string is shorthand for loops over all letters: multiply the inputs, add into the output entry named by the output letters. Letters missing from the output get summed, because many loop iterations land on the same output entry.

For 'ik,kj->ij' the letters are $i,k,j$ and the loop body is

for i, k, j in all index triples:
    C[i, j] += A[i, k] * B[k, j]     # k not in output: summed

The iterations with the same $(i,j)$ and different $k$ add into one entry, so

$$C_{ij}=\sum_kA_{ik}B_{kj}.$$

The same expansion in general:

$$\text{out}[\text{output letters}]=\sum_{\text{other letters}}\ \prod_{\text{inputs}}\text{input}[\text{its letters}].$$

OperationeinsumExpanded
dot product'i,i->'$s=\sum_i x_iy_i$
outer product'i,j->ij'$P_{ij}=x_iy_j$ (nothing summed)
matmul'ik,kj->ij'$C_{ij}=\sum_k A_{ik}B_{kj}$
batch matmul'bik,bkj->bij'$C_{bij}=\sum_k A_{bik}B_{bkj}$
row sums'ij->i'$r_i=\sum_j A_{ij}$
attention scores'bhqd,bhkd->bhqk'$S_{bhqk}=\sum_d Q_{bhqd}K_{bhkd}$

Matmul's string is the "entry = row · column" view from Four views: the shared $k$ is the dot product. A letter kept in the output, like $b$, is a loop that is never summed: one matmul per $b$.

Cost. The body runs once per combination of all letters; with two inputs that is one multiply-add each:

$$\#\text{multiply-adds}=\prod_{\text{all letters}}(\text{size of that letter}).$$

Matmul: $n_i\,n_k\,n_j$. The attention example below: $B\,H\,T\,T\,D=2\cdot4\cdot16\cdot16\cdot32=65{,}536$.

Example: attention scores

B, H, T, D = 2, 4, 16, 32
q, k = torch.randn(B, H, T, D), torch.randn(B, H, T, D)
s = torch.einsum('bhqd,bhkd->bhqk', q, k) / D**0.5    # (2, 4, 16, 16)
torch.allclose(s, q @ k.transpose(-2, -1) / D**0.5, atol=1e-5)   # True

Shape. Read the sizes off the inputs: $b=2$, $h=4$, $q=16$ (axis 2 of q), $k=16$ (axis 2 of k), $d=32$. The output keeps $bhqk$: $(2,4,16,16)$. $d$ is missing, so it is summed: every query dotted with every key, per batch and head.

Same as @. k.transpose(-2, -1) has entries $K^T_{bhdk}=K_{bhkd}$, and @ sums the last axis of the left operand against the second-to-last of the right:

$$(QK^T)_{bhqk}=\sum_dQ_{bhqd}K^T_{bhdk}=\sum_dQ_{bhqd}K_{bhkd}=S_{bhqk}.$$

Why divide by $\sqrt D$. For independent entries with mean $0$ and variance $1$ (what randn gives), each product has $\operatorname{Var}(Q_dK_d)=\mathbb E[Q_d^2]\,\mathbb E[K_d^2]=1$, and variances of independent terms add (variance algebra):

$$\operatorname{Var}\Big(\sum_{d=1}^{D}Q_dK_d\Big)=D\quad\Rightarrow\quad\operatorname{Var}\Big(\frac{S}{\sqrt D}\Big)=\frac{D}{D}=1.$$

Unscaled, these scores would have standard deviation $\sqrt{32}\approx5.7$, enough to saturate a softmax.

Work it out yourself

Batched bilinear form: $s_b=x_b^TA\,y_b$ with $x$ of shape (B, n), $A$ of shape (n, m), $y$ of shape (B, m). Write it with einsum. Then let $A$ have $K$ matrices, shape (K, n, m): what is the string and the output shape?

Solution

Write it with indices first: $x_b^TAy_b$ sums over both inner indices,

$$s_b=\sum_i\sum_jx_{bi}\,A_{ij}\,y_{bj}.$$

Letters $b,i,j$; only $b$ survives. So torch.einsum('bi,ij,bj->b', x, A, y), shape (B,). It equals ((x @ A) * y).sum(-1); do the sums one at a time:

$$(xA)_{bj}=\sum_ix_{bi}A_{ij},\qquad \sum_j(xA)_{bj}\,y_{bj}=s_b.\ \checkmark$$

With $K$ matrices, $A_{ij}$ becomes $A_{kij}$ and $k$ is kept:

$$s_{bk}=\sum_{i,j}x_{bi}\,A_{kij}\,y_{bj}.$$

String 'bi,kij,bj->bk', shape (B, K): one score per example per matrix. That is what nn.Bilinear computes (weight shape (K, n, m)), plus a bias.
