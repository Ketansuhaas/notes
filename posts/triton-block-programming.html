In CUDA you write what one thread does. In Triton you write what one program does to a whole tile, and the compiler spreads it over threads.

Threads vs. blocks

A Triton program instance owns BLOCK elements at once. You think in vectors; the compiler handles the thread-level details.

CUDATriton
You writeone threadone program = one tile

Example: $n=900$, BLOCK $=256$

A complete kernel: vector add

Find your tile, build its offsets, guard the tail, load, compute, store.

import torch, triton, triton.language as tl

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(axis=0)               # which tile am I?
    offs = pid * BLOCK + tl.arange(0, BLOCK)  # its BLOCK indices
    mask = offs < n                           # tail guard
    x = tl.load(x_ptr + offs, mask=mask)
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, x + y, mask=mask)
x = torch.randn(900, device="cuda"); y = torch.randn_like(x)
out = torch.empty_like(x)
grid = (triton.cdiv(x.numel(), 256),)      # 4 programs
add_kernel[grid](x, y, out, x.numel(), BLOCK=256)

With num_warps=4 (128 threads), each thread handles $256/128=2$ elements. You never wrote that mapping.

This is the form torch.compile's Inductor emits. Run with TORCH_LOGS="output_code" to read its kernels.

Work it out yourself

Write a fused row-wise softmax for an $M\times n$ matrix: one program per row. Sketch the kernel body. Why subtract the row max?

Solution 
row  = tl.program_id(0)                      # grid = (M,)
offs = tl.arange(0, BLOCK)                   # BLOCK = next_power_of_2(n)
mask = offs < n
x = tl.load(in_ptr + row*stride + offs, mask=mask, other=-float("inf"))
x = x - tl.max(x, axis=0)                    # largest entry becomes 0
num = tl.exp(x)                              # masked lanes: exp(-inf) = 0
den = tl.sum(num, axis=0)
tl.store(out_ptr + row*stride + offs, num / den, mask=mask)

One HBM read and one write per row; max, exp, sum, divide all happen in registers.

Shifting is free: $\frac{e^{x_j-m}}{\sum_k e^{x_k-m}}=\frac{e^{x_j}}{\sum_k e^{x_k}}$. Without it, $e^{x}$ overflows for $x\gt 88$ in fp32 (about $11$ in fp16) and gives $\infty/\infty$. With it, every exponent is $\le0$ and the denominator is $\ge1$.
