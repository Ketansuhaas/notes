The CUDA programming model

You write the code for one thread. CUDA runs it over a grid of blocks of threads, and each thread uses its coordinates to pick its piece of the data.

Grid, blocks, threads

A launch is a grid of blocks. A block is up to 1024 threads that live on one SM and can cooperate. Each thread knows where it sits.

Number the threads globally in order: all of block 0, then all of block 1, and so on. Every block has blockDim.x threads, so

$$\underbrace{\texttt{blockIdx.x}\cdot\texttt{blockDim.x}}_{\text{threads in the blocks before mine}}+\underbrace{\texttt{threadIdx.x}}_{\text{threads before me in my block}}$$

threads come before me, and that count is my global index:

$$i=\texttt{blockIdx.x}\cdot\texttt{blockDim.x}+\texttt{threadIdx.x}.$$

A complete kernel: vector add

One thread per element. Launch enough blocks to cover $n$ (round up), and let the surplus threads do nothing.

__global__ void add(const float* x, const float* y, float* out, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;  // my element
    if (i < n) out[i] = x[i] + y[i];                 // bounds check
}

int threads = 256;                                   // 8 warps per block
int blocks  = (n + threads - 1) / threads;           // ceil(n / threads)
add<<<blocks, threads>>>(x, y, out, n);              // x, y, out live on the GPU

Blocks are independent and may run in any order on any SM. That is what lets one kernel scale from a laptop GPU to an H100.

Why (n + t - 1) / t is $\lceil n/t\rceil$. C integer division rounds down. Write $n=qt+r$ with $0\le r\lt t$:

$$r=0:\quad \Big\lfloor\frac{qt+t-1}{t}\Big\rfloor=q+\Big\lfloor\frac{t-1}{t}\Big\rfloor=q=\frac nt.$$

$$r\ge1:\quad \Big\lfloor\frac{qt+r+t-1}{t}\Big\rfloor=q+1+\Big\lfloor\frac{r-1}{t}\Big\rfloor=q+1,$$

since $0\le r-1\lt t$. Either way it is the fewest blocks covering $n$. The idle threads number $t\cdot\lceil n/t\rceil-n=t-r$ (or $0$), always fewer than one block.

Example: $n=1000$

$$\text{blocks}=\Big\lfloor\frac{1000+255}{256}\Big\rfloor=\lfloor4.90\rfloor=4.$$

$$4\cdot256=1024\ \text{threads},\qquad 1024-1000=24\ \text{idle}.$$

Each element reads two floats and writes one, for one add:

$$I=\frac{1\ \text{FLOP}}{(4+4+4)\ \text{B}}=\frac1{12}\ \text{FLOP/B}\ \ll\ I^\ast,$$

firmly on the roofline's slope.

Cooperation inside a block

Threads of a block share a small, fast __shared__ array on their SM, and __syncthreads() is a barrier: everyone finishes writing before anyone reads. Tiled matmul is built on exactly this.

Work it out yourself

$n=10^6$, 256 threads per block. How many blocks, idle threads, and warps per block? Which element does thread 5 of block 3 handle? What goes wrong without if (i < n)?

Solution

$10^6=3906\cdot256+64$, so $q=3906$, $r=64$:

$$\text{blocks}=\Big\lceil\frac{10^6}{256}\Big\rceil=\lceil3906.25\rceil=3907.$$

$$\text{threads}=3907\cdot256=1{,}000{,}192,\qquad \text{idle}=1{,}000{,}192-10^6=192=256-64.$$

$$\text{warps per block}=\frac{256}{32}=8,\qquad i=\underbrace{3\cdot256}_{\text{blocks }0,1,2}+5=773.$$

Without the check, the last 192 threads read and write past the ends of the arrays: an illegal memory access error, or silent corruption of neighbouring data.
