Modules and the training loop

Ketan Suhaas Saichandran
pytorchmodulestraining-loop

Builds on: Autograd in PyTorch, Backpropagation via Jacobian-vector products · Leads to: Optimizers and their memory

A model is a tree of modules that owns its parameters. Training is one five-line cycle, repeated per batch.

nn.Module: a tree of parameters

A Module stores parameters (leaf tensors with requires_grad=True) and child modules, and defines forward. Assigning a child as an attribute registers it, so model.parameters() finds every weight in the tree.

import torch, torch.nn as nn
class MLP(nn.Module):
    def __init__(self, d_in, d_hid, d_out):
        super().__init__()
        self.fc1 = nn.Linear(d_in, d_hid)   # weight (d_hid, d_in), bias (d_hid,)
        self.fc2 = nn.Linear(d_hid, d_out)
    def forward(self, x):                   # x: (B, d_in)
        return self.fc2(torch.relu(self.fc1(x)))

model = MLP(784, 256, 10)
sum(p.numel() for p in model.parameters())  # 203530
model(x)runs forward (plus hooks)
model.parameters()every weight, for the optimizer
model.to('cuda')moves every parameter and buffer

Example

nn.Linear(d_in, d_out) computes $y=Wx+b$. Each of the $d_{\text{out}}$ outputs is $\sum_jW_{ij}x_j+b_i$: $d_{\text{in}}$ weights plus $1$ bias, so

$$\#\text{params}=d_{\text{out}}\,(d_{\text{in}}+1).$$

$$\text{fc1: }256\cdot(784+1)=200{,}960,\qquad \text{fc2: }10\cdot(256+1)=2{,}570.$$

Total $200{,}960+2{,}570=203{,}530$, about $0.8$ MB in fp32 ($\times4$ bytes).

The training loop

Predict, score, clear old gradients, compute new ones, nudge the weights. Then the next batch.

opt = torch.optim.SGD(model.parameters(), lr=0.1)
loss_fn = nn.CrossEntropyLoss()
for x, y in loader:               # x: (B, 784), y: (B,) int64
    logits = model(x)             # 1. forward: (B, 10), graph recorded
    loss = loss_fn(logits, y)     # 2. loss: a scalar
    opt.zero_grad()               # 3. clear .grad
    loss.backward()               # 4. fill .grad, free the graph
    opt.step()                    # 5. p -= lr * p.grad

Where each line's math comes from:

2. Loss. CrossEntropyLoss averages the negative log softmax probability of the true class over the batch, so it returns one number:

$$\ell_b=-\log\frac{e^{z_{b,y_b}}}{\sum_ce^{z_{b,c}}}=-z_{b,y_b}+\log\sum_ce^{z_{b,c}},\qquad L=\frac1B\sum_{b=1}^B\ell_b.$$

4. Backward starts from $\partial L/\partial z$. Differentiate $\ell_b$ term by term:

$$\frac{\partial\ell_b}{\partial z_{b,c}}=-\mathbb 1[c=y_b]+\frac{e^{z_{b,c}}}{\sum_{c'}e^{z_{b,c'}}}=\operatorname{softmax}(z_b)_c-\mathbb 1[c=y_b],$$

times $\tfrac1B$ from the mean; then it flows back through fc2, ReLU, fc1 as in Autograd.

3 before 4. backward() adds into .grad (Autograd), so last batch's gradient must be cleared first. 5. Plain SGD, $\theta\leftarrow\theta-\eta\,g$ (derived in Optimizers).

train() and eval()

A few layers act differently while training. model.eval() flips every submodule to its deterministic inference behavior.

Layertrain()eval()
Dropout($p$)zero each unit with prob. $p$, scale the rest by $\tfrac1{1-p}$identity
BatchNormnormalize with this batch's mean/var; update running statsuse the running stats

Why Dropout scales by $\tfrac1{1-p}$. In training a unit becomes $h\,m/(1-p)$ with mask $m\sim\text{Bernoulli}(1-p)$. Its expected value matches what eval() passes through unchanged:

$$\mathbb E\Big[\frac{h\,m}{1-p}\Big]=\frac{h\,\mathbb E[m]}{1-p}=\frac{h\,(1-p)}{1-p}=h.$$

So the next layer sees the same mean input in both modes. Example $p=0.5$: survivors are doubled, half of them vanish, average unchanged.

BatchNorm. In training, with this batch's mean $\mu_B$ and variance $\sigma_B^2$ per channel:

$$\hat x=\frac{x-\mu_B}{\sqrt{\sigma_B^2+\epsilon}},\qquad \mu_{\text{run}}\leftarrow(1-\alpha)\,\mu_{\text{run}}+\alpha\,\mu_B,$$

with $\alpha=0.1$ by default (same update for $\sigma^2_{\text{run}}$): an exponential moving average, the same tool Adam uses (Optimizers). eval() uses $\mu_{\text{run}},\sigma^2_{\text{run}}$ instead, so an example's output no longer depends on what else is in its batch.

model.eval()                 # mode flag only: autograd still records
with torch.no_grad():        # so also turn recording off
    val_logits = model(x_val)
model.train()

Work it out yourself

Delete opt.zero_grad() from the loop. What does p.grad hold at step $t$, and what happens to training? When is this behavior useful on purpose?

Solution

Let $G_t$ be p.grad after the $t$-th backward and $g_t$ that batch's gradient. backward() adds, nobody clears:

$$G_t=G_{t-1}+g_t,\quad G_0=0\qquad\Rightarrow\qquad G_t=\sum_{s=1}^tg_s.$$

That is momentum's $v_t=\mu v_{t-1}+g_t$ with $\mu=1$: no decay, nothing forgotten. If the gradients point roughly the same way, $g_s\approx g$, the step grows linearly:

$$\theta_t-\theta_{t-1}=-\eta\,G_t\approx-\eta\,t\,g.$$

By step $100$ the effective learning rate is $100\eta$, so training goes erratic or diverges.

On purpose: gradient accumulation. Want batch $kB$ but only $B$ fits in memory? Run $k$ backward passes, then one step.

for i, (x, y) in enumerate(loader):
    loss = loss_fn(model(x), y) / k   # / k: average over k*B examples
    loss.backward()                   # adds into .grad
    if (i + 1) % k == 0:
        opt.step()
        opt.zero_grad()

Why the $/k$ gives the same gradient as one batch of $kB$. Each micro-batch loss is a mean over its $B$ examples, and the $k$ backward calls add (linearity of the gradient):

$$G=\sum_{j=1}^k\nabla\Big(\frac1k\cdot\frac1B\sum_{i\in\text{batch }j}\ell_i\Big)$$

$$=\frac1{kB}\sum_{j=1}^k\sum_{i\in\text{batch }j}\nabla\ell_i,$$

which is the gradient of the mean loss over all $kB$ examples. Without $/k$ it would be $k$ times too big. (Exact only for layers that treat examples independently: BatchNorm still sees batches of $B$.)
