Modules and the training loop

Ketan Suhaas Saichandran
pytorchmodulestraining-loop

Builds on: Autograd in PyTorch, Backpropagation via Jacobian-vector products · Leads to: Optimizers and their memory

A model is a tree of modules that owns its parameters. Training is one five-line cycle, repeated per batch.

nn.Module: a tree of parameters

A Module stores parameters (leaf tensors with requires_grad=True) and child modules, and defines forward. Assigning a child as an attribute registers it, so model.parameters() finds every weight in the tree.

import torch, torch.nn as nn
class MLP(nn.Module):
    def __init__(self, d_in, d_hid, d_out):
        super().__init__()
        self.fc1 = nn.Linear(d_in, d_hid)   # weight (d_hid, d_in), bias (d_hid,)
        self.fc2 = nn.Linear(d_hid, d_out)
    def forward(self, x):                   # x: (B, d_in)
        return self.fc2(torch.relu(self.fc1(x)))

model = MLP(784, 256, 10)
sum(p.numel() for p in model.parameters())  # 203530
model(x)runs forward (plus hooks)
model.parameters()every weight, for the optimizer
model.to('cuda')moves every parameter and buffer
model.state_dict()name → tensor, for saving

Example

$784\cdot256+256=200{,}960$ and $256\cdot10+10=2{,}570$: total $203{,}530$.

The training loop

Predict, score, clear old gradients, compute new ones, nudge the weights. Then the next batch.

opt = torch.optim.SGD(model.parameters(), lr=0.1)
loss_fn = nn.CrossEntropyLoss()
for x, y in loader:               # x: (B, 784), y: (B,) int64
    logits = model(x)             # 1. forward: (B, 10), graph recorded
    loss = loss_fn(logits, y)     # 2. loss: a scalar
    opt.zero_grad()               # 3. clear .grad
    loss.backward()               # 4. fill .grad, free the graph
    opt.step()                    # 5. p -= lr * p.grad

Work it out yourself

Delete opt.zero_grad() from the loop. What does p.grad hold at step $t$, and what happens to training? When is this behavior useful on purpose?

Solution

p.grad $=g_1+g_2+\dots+g_t$: every past gradient, never forgotten. Each step moves along this growing sum, like momentum with no decay, so steps grow and training goes erratic or diverges.

On purpose: gradient accumulation. Want batch $kB$ but only $B$ fits in memory? Run $k$ backward passes, then one step.

for i, (x, y) in enumerate(loader):
    loss = loss_fn(model(x), y) / k   # / k: average over k*B examples
    loss.backward()                   # adds into .grad
    if (i + 1) % k == 0:
        opt.step()
        opt.zero_grad()

Same gradient as one batch of $kB$ (BatchNorm still sees batches of $B$).
