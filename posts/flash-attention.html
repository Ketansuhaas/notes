FlashAttention: tiling plus online softmax

Ketan Suhaas Saichandran
gpuattentionflash-attentionsoftmaxkernel-fusion

Builds on: Tiled matrix multiplication, Kernel fusion and torch.compile, Triton: programming GPUs in blocks

Attention's cost is not the math, it is the $n\times n$ score matrix round-tripping through HBM. FlashAttention never writes it: it tiles, and fixes up the softmax as it goes.

Standard attention materializes $S$

Every query meets every key, so the scores form an $n\times n$ matrix. The standard path writes it to HBM, reads it for softmax, writes $P$, reads $P$ again.

$$\underbrace{S}_{n\times n}=\frac{QK^T}{\sqrt d},\qquad P=\operatorname{softmax}_{\text{row}}(S),\qquad \underbrace{O}_{n\times d}=PV.$$

Example: $n=8192$, $d=128$, BF16, one head

$Q,K,V,O$$4\times2$ MB
$S$ or $P$$134$ MB each
HBM traffic for $S,P$ (write, read, write, read)$\approx540$ MB

Each entry is 2 B:

$$Q:\ n\cdot d\cdot2=8192\cdot128\cdot2=2^{21}\ \text{B}\approx2.1\ \text{MB}\ \ (\text{same for }K,V,O).$$

$$S:\ n\cdot n\cdot2=8192^2\cdot2=2^{27}\ \text{B}\approx134\ \text{MB},\qquad \frac{|S|}{|Q|}=\frac nd=64.$$

$$\text{traffic: }\underbrace{4}_{\text{W }S,\ \text{R }S,\ \text{W }P,\ \text{R }P}\times134\ \text{MB}\approx537\ \text{MB}.$$

Bytes beat math. Count the two matmuls as in the roofline note (outputs $\times$ 2 $\times$ inner length):

$$QK^T:\ n^2\cdot2d,\qquad PV:\ nd\cdot2n\qquad\Rightarrow\qquad 2n^2d\ \text{FLOPs each}.$$

With A100 specs (~312 TFLOP/s, ~2 TB/s, approximate):

$$\text{math: }\frac{2\cdot2n^2d}{3.12\times10^{14}}=\frac{3.4\times10^{10}}{3.12\times10^{14}}\approx0.11\ \text{ms}.$$

$$\text{moving }S,P:\ \frac{5.37\times10^{8}}{2\times10^{12}}\approx0.27\ \text{ms}.$$

Shuffling $S$ and $P$ costs more than all the matmul math. Both $S$ and $P$ hold $n^2$ numbers, so this extra memory grows as $O(n^2)$, and the softmax is a memory-bound pass over it (a few FLOPs per 4 B, far below the ridge).

Online softmax

Softmax needs the row's max and sum over all keys. You can get both in one streaming pass: keep a running max $m$ and sum $\ell$, and rescale the old totals whenever the max grows.

Step 1: what one output row is. Fix a query. Its scores are $s_1,\dots,s_n$, its value rows $v_1,\dots,v_n$. By definition of softmax and $O=PV$:

$$O=\sum_j p_j\,v_j,\qquad p_j=\frac{e^{s_j}}{\sum_k e^{s_k}}.$$

Step 2: shift by any $m$. Multiplying top and bottom by $e^{-m}$ changes nothing (as in Triton softmax):

$$O=\frac{\sum_j e^{s_j-m}\,v_j}{\sum_j e^{s_j-m}}=\frac{o}{\ell},\qquad \ell:=\sum_j e^{s_j-m},\quad o:=\sum_j e^{s_j-m}\,v_j.$$

So keep three running quantities for the keys seen so far: $m$ (their max, for safety), $\ell$ and $o$ (defined with that $m$).

Step 3: a new block arrives. Let $\mathcal S$ be the keys seen so far and $\mathcal N$ the new block. The max of a union is the max of the maxes:

$$m'=\max\!\big(m,\ \max_{j\in\mathcal N} s_j\big).$$

Split the new sum into old and new keys, and rewrite each old term with $e^{s_j-m'}=e^{s_j-m}\,e^{m-m'}$:

$$\ell'=\sum_{j\in\mathcal S\cup\mathcal N}e^{s_j-m'}=e^{m-m'}\underbrace{\sum_{j\in\mathcal S}e^{s_j-m}}_{\ell}+\sum_{j\in\mathcal N}e^{s_j-m'}.$$

The same split with an extra $v_j$ in every term gives $o'$:

$$o'=e^{m-m'}\,o+\sum_{j\in\mathcal N}e^{s_j-m'}\,v_j.$$

Step 4: start and finish. Before any keys, $\mathcal S$ is empty: $\ell=0$, $o=0$, and $m=-\infty$ (then $e^{m-m'}=0$, so the first update is just the new block's sums). After the last block, Step 2 gives the exact answer $O=o/\ell$. The old totals are only ever multiplied by $e^{m-m'}\le1$, so nothing overflows.

Tiling: $S$ only exists one tile at a time

Each program owns a block of query rows and keeps $Q_i$, $m$, $\ell$, $o$ in SRAM. It streams $K_j,V_j$ blocks past, computing one score tile, folding it in, discarding it.

Where $O(n^2)$ vs $O(n)$ comes from. Count what must sit in HBM besides $Q,K,V,O$ (which are $4nd$ either way):

$$\text{standard: }\underbrace{n^2}_{S}+\underbrace{n^2}_{P}=2n^2,\qquad \text{Flash: }\underbrace{n}_{m}+\underbrace{n}_{\ell}=2n.$$

Flash keeps $m,\ell$ per row for the backward pass. Everything else lives in one program's SRAM: a $B_r\times d$ query block, $B_c\times d$ key and value blocks, a $B_r\times B_c$ score tile, and $B_r$ copies of $m,\ell,o$. None of that depends on $n$. In the example, Flash's extra is $2\cdot8192\cdot4$ B $=64$ KB (fp32) instead of $2\times134$ MB.

In PyTorch, F.scaled_dot_product_attention(q, k, v, is_causal=True) picks a FlashAttention kernel when the GPU, dtype and shapes allow it.

Derive it yourself

Split a row's scores into blocks $A$ and $B$ with $m_A=\max_A s_j$, $\ell_A=\sum_{A}e^{s_j-m_A}$ (same for $B$). Show that $m=\max(m_A,m_B)$ and $\ell=e^{m_A-m}\ell_A+e^{m_B-m}\ell_B$ give the exact softmax normalizer.

Solution

$$e^{m_A-m}\,\ell_A=\sum_{A}e^{m_A-m}\,e^{s_j-m_A}=\sum_{A}e^{s_j-m}.$$

Same for $B$, so $\ell=\sum_{A\cup B}e^{s_j-m}=e^{-m}\sum_{\text{all}}e^{s_j}$.

Then $e^{s_j-m}/\ell=e^{s_j-m}/\big(e^{-m}\sum_k e^{s_k}\big)=e^{s_j}/\sum_k e^{s_k}$: exactly softmax. Since $m$ is the true max, every exponent is $\le0$, so nothing overflows. The same factor rescales $o$, term by term:

$$e^{m_A-m}o_A+e^{m_B-m}o_B=\sum_{A\cup B}e^{s_j-m}v_j=o\quad\Rightarrow\quad \frac o\ell=\sum_j p_jv_j.$$

This merge is Step 3 with $\mathcal S=A$, $\mathcal N=B$; it also lets two programs split one row's keys and combine at the end.
