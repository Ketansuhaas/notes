Why GPUs: latency vs. throughput

Ketan Suhaas Saichandran
gpuhardwarethroughputlatency

Builds on: Datasets and DataLoaders, Four views of matrix multiplication · Leads to: Inside a GPU: SMs, warps, and memory

A CPU makes one task finish fast. A GPU makes a million identical tasks finish fast. Training a network is the second kind of job.

Two ways to spend a chip

Latency = time for one task. Throughput = tasks per second. A CPU buys low latency with control logic and cache; a GPU spends that area on arithmetic.

Rough numbers

server CPUGPU (A100)
cores~8 to 64 big cores108 SMs, ~7000 FP32 lanes
clock~3 to 5 GHz~1.4 GHz
peak math~1 TFLOP/s~312 TFLOP/s (bf16)
memory bandwidth~0.1 to 0.5 TB/s~2 TB/s

Hiding memory latency

A read from GPU memory takes hundreds of cycles. A CPU avoids the wait with big caches and branch prediction; a GPU simply switches to another group of threads that is ready.

Example

An A100 SM keeps up to 2048 threads resident, so the chip juggles $108\times2048\approx221{,}000$ threads. A GPU needs that much parallel work to stay busy.

Deep learning is a throughput job

Every layer applies the same arithmetic to millions of numbers, with no data-dependent branching. That is the GPU's ideal workload.

linear layer, 4096 tokens, $4096\to4096$$2\cdot4096^3\approx1.4\times10^{11}$ FLOPs of identical multiply-adds
ReLU on a $4096\times4096$ activation$1.7\times10^{7}$ independent max ops

Work it out yourself

(a) $10^{12}$ FLOPs of matmul on a ~1 TFLOP/s CPU vs a ~300 TFLOP/s GPU. (b) Add 1 to $10^9$ fp32 numbers (read and write each once) with ~0.2 TB/s vs ~2 TB/s of memory bandwidth. Why is (b)'s speedup so much smaller?

Solution

(a) CPU: $1$ s. GPU: $10^{12}/(3\times10^{14})\approx3.3$ ms. About $300\times$.

(b) Bytes: $10^9\cdot(4+4)=8$ GB. CPU: $40$ ms. GPU: $4$ ms. Only $10\times$. The math is ~1 ms even on the CPU; the time goes to moving bytes, and the bandwidth gap is ~$10\times$, not $300\times$.

Real programs mix both kinds of work (plus kernel launches and CPU-to-GPU copies), so speedups land in between. Where those bytes live is the next note.
