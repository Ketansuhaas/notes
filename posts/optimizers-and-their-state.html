Optimizers and their memory

Ketan Suhaas Saichandran
pytorchoptimizersadammemory

Builds on: Modules and the training loop, Gradient descent on a quadratic · Leads to: Datasets and DataLoaders

An optimizer turns p.grad into a step. Smarter steps remember the past, and that memory is a full-size tensor per parameter.

SGD: step downhill

Move against the gradient. Nothing to remember.

$$\theta\leftarrow\theta-\eta\,g. \qquad \text{State: none.}$$

Momentum: a running direction

Keep a velocity that sums recent gradients. Consistent directions build speed; the zig-zag across a narrow valley (GD on a quadratic) cancels out.

$$v\leftarrow\mu v+g,\qquad \theta\leftarrow\theta-\eta\,v. \qquad \text{State: } v\ (\text{one tensor}).$$

Adam: momentum plus a per-coordinate step size

Also track the average squared gradient. Coordinates with big, noisy gradients get small steps; quiet ones get big steps: a cheap diagonal preconditioner.

$$m\leftarrow\beta_1m+(1-\beta_1)g,\qquad v\leftarrow\beta_2v+(1-\beta_2)g^2,$$ $$\theta\leftarrow\theta-\eta\,\frac{\hat m}{\sqrt{\hat v}+\epsilon},\qquad \hat m=\frac{m}{1-\beta_1^t},\ \hat v=\frac{v}{1-\beta_2^t}.$$

Defaults $\beta_1=0.9$, $\beta_2=0.999$, $\epsilon=10^{-8}$. AdamW adds decoupled weight decay $\theta\leftarrow\theta-\eta\lambda\theta$. The hats undo the bias of starting $m,v$ at $0$.

opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)
loss_fn(model(x), y).backward()
opt.step()                       # state is created on the first step
p = next(model.parameters())
opt.state[p].keys()              # dict_keys(['step', 'exp_avg', 'exp_avg_sq'])
opt.state[p]['exp_avg'].shape == p.shape    # True: m, v are full-size

The memory bill

Training holds far more than the weights. In fp32: 4 bytes weight + 4 grad + 8 for Adam's $m,v$ = 16 bytes per parameter, $4\times$ the model. Activations come on top.

gradients4 GB

Work it out yourself

A 7B-parameter model trained with Adam. Memory before activations (a) all in fp32; (b) bf16 weights and grads, fp32 $m$ and $v$. Does either fit on one 80 GB GPU?

Solution

(a) $16$ bytes $\times\,7\cdot10^9=112$ GB.

(b) $2+2+4+4=12$ bytes: $84$ GB. In practice mixed precision also keeps an fp32 master copy of the weights, since bf16 (about 3 significant digits) rounds tiny updates away: $+4$ bytes, back to $16$ bytes $=112$ GB. Mixed precision saves activation memory and time, not this bill.

Neither fits in 80 GB even before activations. Hence sharding weights, grads and optimizer state across GPUs (ZeRO, FSDP).
