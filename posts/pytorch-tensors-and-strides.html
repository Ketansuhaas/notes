A tensor is a flat row of numbers in memory plus a small recipe for reading it as an array. Many operations rewrite only the recipe.

Five fields

Strides: the address rule

Element $[i,j]$ sits at offset $i\,s_0+j\,s_1$. Transposing swaps the strides; slicing moves the start. No data moves.

$$\text{offset}(i,j)=\text{start}+i\,s_0+j\,s_1.$$

x = torch.arange(6.).view(2, 3)
x.stride()                  # (3, 1)
x.T.stride()                # (1, 3)   same storage
x[:, 1:].stride()           # (3, 1)   shape (2, 2)
x[:, 1:].storage_offset()   # 1        starts one element in
x.T.data_ptr() == x.data_ptr()   # True: no copy

Contiguous, and why .view can fail

Contiguous means row-major: last stride $1$, each stride = product of the sizes after it. .view only re-strides the same buffer, so on a scrambled layout it may be impossible.

x.T.is_contiguous()          # False: stride (1, 3), not (2, 1)
x.T.view(6)                  # RuntimeError: use .reshape(...)
x.T.reshape(6)               # tensor([0., 3., 1., 4., 2., 5.])  copies
x.T.contiguous().stride()    # (2, 1): fresh row-major buffer
OperationCopies data?
.T, transpose, permute, slicing, expandnever (new strides only)
.viewnever (errors if impossible)
.reshape, .contiguous()only when needed

dtype: bytes per number

Memory and bandwidth scale with bytes per element. Halving the dtype halves both.

dtypeBytesTypical use
float324default floats, optimizer state
bfloat162training and inference; fp32's range, fewer digits
float162inference; narrow range (max 65504)
int648default integers: indices, class labels

Example

$10^9$ parameters: $4$ GB in fp32, $2$ GB in bf16. Check any tensor with x.element_size() * x.numel().

device: moving is a copy

Operands must live on the same device. .to('cuda') allocates GPU memory and copies the bytes over PCIe.

x = torch.randn(4096, 4096)                # CPU, 64 MB fp32
y = x.to('cuda')                           # new storage on the GPU
z = x.to('cuda', dtype=torch.bfloat16)     # copy + cast: 32 MB
x + y                                      # RuntimeError: different devices

64 MB over PCIe 4.0 (roughly 25 GB/s): a few ms. The A100 reads its own memory at roughly 2 TB/s. Move data once, not every step.

Work it out yourself

x = torch.zeros(4, 5). Predict shape, stride and storage offset of x.T and x[:, 1:]. Which of the three can call .view(-1)?

Solution
