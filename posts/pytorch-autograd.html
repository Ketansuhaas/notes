Autograd in PyTorch

Ketan Suhaas Saichandran
pytorchautogradgradientsautomatic-differentiation

Builds on: Automatic differentiation, Broadcasting and einsum · Leads to: Modules and the training loop

Autograd is reverse-mode autodiff that records itself. Every op on a watched tensor runs and also leaves a node behind; .backward() walks those nodes in reverse.

The graph is built as the code runs

Mark leaves with requires_grad=True. Each result gets a grad_fn: the node that knows its local vector-Jacobian product. A fresh graph is recorded every forward pass, so ordinary Python ifs and loops just work.

x = torch.tensor(2.0, requires_grad=True)
w = torch.tensor(3.0, requires_grad=True)
y = w * x           # y.grad_fn: <MulBackward0>
z = y + x           # z.grad_fn: <AddBackward0>
L = z ** 2          # L.grad_fn: <PowBackward0>
L.backward()        # reverse sweep, seed dL/dL = 1
x.grad, w.grad      # (tensor(64.), tensor(32.))

Forward (values each node will need later):

$$y=wx=3\cdot2=6,\qquad z=y+x=6+2=8,\qquad L=z^2=64.$$

Backward. Write $\bar v=\partial L/\partial v$ (the adjoint, as in Automatic differentiation). Each node multiplies the adjoint arriving from its output by its local derivative and passes the result to each input. Seed $\bar L=1$.

$$\text{Pow: } \bar z=\bar L\cdot\frac{\partial(z^2)}{\partial z}=1\cdot2z=16.$$

$$\text{Add: } \frac{\partial z}{\partial y}=\frac{\partial z}{\partial x}=1\ \Rightarrow\ \bar y=16,\quad \bar x\mathrel{+}=16.$$

$$\text{Mul: } \frac{\partial y}{\partial w}=x=2,\qquad \frac{\partial y}{\partial x}=w=3$$

$$\Rightarrow\quad \bar w=\bar y\cdot2=32,\qquad \bar x\mathrel{+}=\bar y\cdot3=48.$$

$$\text{AccumulateGrad: } \texttt{x.grad}=16+48=64,\qquad \texttt{w.grad}=32.$$

Check against the closed form $L=(wx+x)^2=x^2(w+1)^2$:

$$\frac{\partial L}{\partial x}=2x(w+1)^2=2\cdot2\cdot16=64,\qquad \frac{\partial L}{\partial w}=2x^2(w+1)=2\cdot4\cdot4=32.\ \checkmark$$

Gradients accumulate

backward() adds into .grad, never overwrites. That is how a value used twice collects both terms, and why you must clear grads between steps.

Why "add" is the right operation. Above, $x$ feeds two nodes. Give each use its own name, $u_1=x$ (into Add) and $u_2=x$ (into Mul), so $L=F(u_1,u_2)$. The multivariable chain rule:

$$\frac{dL}{dx}=\frac{\partial F}{\partial u_1}\underbrace{\frac{du_1}{dx}}_{1}+\frac{\partial F}{\partial u_2}\underbrace{\frac{du_2}{dx}}_{1}=16+48=64.$$

One term per use, summed. The engine implements that sum as "$\mathrel{+}=$ into the adjoint", one contribution at a time (Automatic differentiation). A second backward() looks to .grad exactly like more uses, so it keeps adding:

x.grad = None           # clear (what optimizer.zero_grad() does)
for _ in range(2):
    L = (w * x + x) ** 2
    L.backward()
    print(x.grad)       # tensor(64.), then tensor(128.): added

$$\text{call 1: } 0+64=64,\qquad \text{call 2: } 64+64=128.$$

Turning recording off

Recording costs memory: every node keeps the inputs it needs for its backward. Switch it off when you will not differentiate.

What a node must keep is read off its local derivatives in the example above:

$$\text{Pow needs } 2z\Rightarrow\text{saves } z;\quad \text{Mul needs } x,w\Rightarrow\text{saves both};\quad \text{Add needs } 1\Rightarrow\text{saves nothing}.$$

A linear layer $y=Wx$ has $\bar W=\bar y\,x^T$, so it saves its input $x$: one activation tensor per layer stays alive until backward().

with torch.no_grad():nothing inside is recorded (evaluation, weight updates)
t.detach()same storage, cut from the graph: a constant to autograd
p.requires_grad_(False)freeze a parameter
with torch.no_grad():
    w -= 0.1 * w.grad   # in-place update, not recorded
c = (w * x).detach()    # c.requires_grad == False

Vector outputs need a vector

Reverse mode computes $u^TJ$. For a scalar loss $u=1$ is implied. For a vector output you must pass $u$, shaped like the output.

Where $u^TJ$ comes from: if $y=f(x)$ feeds some scalar $L$, the chain rule sums over the outputs,

$$\frac{\partial L}{\partial x_j}=\sum_i\frac{\partial L}{\partial y_i}\frac{\partial y_i}{\partial x_j}=\sum_iu_iJ_{ij}=(u^TJ)_j,\qquad u=\frac{\partial L}{\partial y}.$$

When $y$ is itself the scalar $L$, $u=\partial L/\partial L=1$. Otherwise autograd has no $L$, so you supply $u$.

x = torch.tensor([1., 2., 3.], requires_grad=True)
y = x ** 2                  # J = diag(2x)
y.backward(torch.ones(3))   # u^T J with u = 1: same as y.sum().backward()
x.grad                      # tensor([2., 4., 6.])

Here $y_i=x_i^2$, so $J_{ij}=\partial y_i/\partial x_j=2x_i$ if $i=j$, else $0$. With $u=(1,1,1)$:

$$(u^TJ)_j=\sum_iu_iJ_{ij}=u_j\,2x_j=2x_j=(2,4,6).$$

This is also the gradient of $\sum_iy_i$, since $\partial(\sum_iy_i)/\partial x_j=\sum_iJ_{ij}=(\mathbf 1^TJ)_j$: hence "same as y.sum().backward()". Plain y.backward() here raises "grad can be implicitly created only for scalar outputs".

Derive it yourself

a = [1., 2.], b = [3., 4.], both with requires_grad=True. L = (a * b).sum() + (a ** 2).sum(), then L.backward(). What are a.grad and b.grad? You recompute L and call backward() again without zeroing: now what?

Solution

Write it per index: $L=\sum_i(a_ib_i+a_i^2)$. Only the $i=j$ term involves $a_j$ or $b_j$. $a_j$ has two uses (in a * b and in a ** 2), so its gradient is a sum of two terms:

$$\frac{\partial L}{\partial a_j}=\underbrace{b_j}_{\text{from }a_jb_j}+\underbrace{2a_j}_{\text{from }a_j^2}\ \Rightarrow\ (3+2,\ 4+4)=(5,\,8).$$

$$\frac{\partial L}{\partial b_j}=a_j\ \Rightarrow\ (1,\,2).$$

Each .sum() passes $u=\mathbf 1$ back to its input (as in the last section), so these are exactly what lands in .grad. The second backward() adds the same amounts again: $(5,8)+(5,8)$ gives a.grad = [10., 16.], $(1,2)+(1,2)$ gives b.grad = [2., 4.].
