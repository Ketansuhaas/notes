Autograd in PyTorch

Ketan Suhaas Saichandran
pytorchautogradgradientsautomatic-differentiation

Builds on: Automatic differentiation, Broadcasting and einsum · Leads to: Modules and the training loop

Autograd is reverse-mode autodiff that records itself. Every op on a watched tensor runs and also leaves a node behind; .backward() walks those nodes in reverse.

The graph is built as the code runs

Mark leaves with requires_grad=True. Each result gets a grad_fn: the node that knows its local vector-Jacobian product. A fresh graph is recorded every forward pass, so ordinary Python ifs and loops just work.

x = torch.tensor(2.0, requires_grad=True)
w = torch.tensor(3.0, requires_grad=True)
y = w * x           # y.grad_fn: <MulBackward0>
z = y + x           # z.grad_fn: <AddBackward0>
L = z ** 2          # L.grad_fn: <PowBackward0>
L.backward()        # reverse sweep, seed dL/dL = 1
x.grad, w.grad      # (tensor(64.), tensor(32.))

Check by hand: $L=(wx+x)^2$, $\partial L/\partial z=2z=16$. $x$ has two paths, so $\partial L/\partial x=16w+16=64$ and $\partial L/\partial w=16x=32$. ✓

Gradients accumulate

backward() adds into .grad, never overwrites. That is how a value used twice collects both terms, and why you must clear grads between steps.

x.grad = None           # clear (what optimizer.zero_grad() does)
for _ in range(2):
    L = (w * x + x) ** 2
    L.backward()
    print(x.grad)       # tensor(64.), then tensor(128.): added

Turning recording off

Recording costs memory: every node keeps the inputs it needs for its backward. Switch it off when you will not differentiate.

with torch.no_grad():nothing inside is recorded (evaluation, weight updates)
t.detach()same storage, cut from the graph: a constant to autograd
p.requires_grad_(False)freeze a parameter
with torch.no_grad():
    w -= 0.1 * w.grad   # in-place update, not recorded
c = (w * x).detach()    # c.requires_grad == False

Vector outputs need a vector

Reverse mode computes $u^TJ$. For a scalar loss $u=1$ is implied. For a vector output you must pass $u$, shaped like the output.

x = torch.tensor([1., 2., 3.], requires_grad=True)
y = x ** 2                  # J = diag(2x)
y.backward(torch.ones(3))   # u^T J with u = 1: same as y.sum().backward()
x.grad                      # tensor([2., 4., 6.])

Plain y.backward() here raises "grad can be implicitly created only for scalar outputs".

Derive it yourself

a = [1., 2.], b = [3., 4.], both with requires_grad=True. L = (a * b).sum() + (a ** 2).sum(), then L.backward(). What are a.grad and b.grad? You recompute L and call backward() again without zeroing: now what?

Solution

$L=\sum_i a_ib_i+a_i^2$, so $\partial L/\partial a=b+2a=(5,\,8)$ and $\partial L/\partial b=a=(1,\,2)$.

Second call adds the same amounts: a.grad = [10., 16.], b.grad = [2., 4.].
