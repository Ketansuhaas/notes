Datasets and DataLoaders

Ketan Suhaas Saichandran

Builds on: Optimizers and their memory, Expectation and variance algebra · Leads to: Why GPUs: latency vs. throughput

The Dataset knows single examples. The DataLoader turns them into a stream of shuffled batches, fast enough to keep the GPU busy.

Dataset: one example at a time

Two methods: how many examples, and give me example $i$. Nothing about batches or order.

from torch.utils.data import Dataset, DataLoader
class Squares(Dataset):
    def __init__(self, n): self.x = torch.arange(n, dtype=torch.float32)
    def __len__(self): return len(self.x)
    def __getitem__(self, i): return self.x[i], self.x[i] ** 2

DataLoader: the batching pipeline

Pick indices, fetch examples in parallel, stack them into one batch, stage it for a fast copy to the GPU.

loader = DataLoader(Squares(1000), batch_size=64, shuffle=True,
                    num_workers=4, pin_memory=True, drop_last=False)
x, y = next(iter(loader))                 # x, y: (64,)
x = x.to('cuda', non_blocking=True)       # async copy from pinned memory
shuffle=Truenew random order every epoch
collate_fnlist of examples → batch (default: stack each field)
num_workersprocesses calling __getitem__ in parallel with training
pin_memorypage-locked host memory: faster, asynchronous copies to the GPU
drop_lastskip the final short batch

Why shuffle

SGD needs each mini-batch gradient to be an honest, noisy estimate of the full gradient. Random batches give that; sorted data does not.

$$\hat g_B=\frac1B\sum_{i\in\text{batch}}\nabla\ell_i, \qquad \mathbb{E}[\hat g_B]=\nabla L, \qquad \operatorname{Var}\approx\frac{\sigma^2}{B}.$$

Example

MNIST sorted by label, batch 64: the first ~90 batches are all "0"s, so every step pushes toward predicting 0, then toward 1, and so on. Each batch gradient is biased; the model chases the latest class. The $\sigma^2/B$ is from variance algebra.

Work it out yourself

$N=50{,}000$ examples, batch_size=64. How many optimizer steps per epoch with drop_last=False and with drop_last=True? How big is the last batch, and why might you drop it?

Solution

$50{,}000=781\cdot64+16$. drop_last=False: $\lceil 50000/64\rceil=782$ steps, the last with only $16$ examples. drop_last=True: $781$ steps; $16$ examples skipped this epoch (different ones each epoch, thanks to shuffling).

Why drop: a batch of $16$ has $4\times$ the gradient variance of $64$ ($\sigma^2/B$), BatchNorm statistics get noisy, and every batch keeping the same shape helps compiled code.
